## 1. Введение и цели

### 1.1. Название и концепция

**Рабочее название:** Психологическая студия.

**Концепция:** гибридная онлайн-платформа для проведения психологических сессий, объединяющая видеосвязь и интерактивный холст с подключаемыми модулями терапевтической работы.

**Ключевая метафора:** «Психологический стол».
- **Видео** — эмпатический контакт, присутствие.
- **Холст** — пространство для терапевтической работы.

### 1.2. Цель

Создать платформу для проведения онлайн-сессий с использованием видео и интерактивных инструментов, с сохранением состояния работы и записью сессии как единого артеfactа (видео + холст).

### 1.3. Прототип

Интерактивный UI-прототип: `index.php`. Прототип подтверждает UX-модель (sidebar, три состояния main area, модули, PiP). Не является production-кодом.

## 2. Архитектура продукта

### 2.1. База и модули

```
┌─────────────────────────────────────────────────┐
│              ПЛАТФОРМА (БАЗА)                    │
│  ┌──────────────┐    ┌──────────────────────┐   │
│  │   Видео      │◄──►│   Холст (ядро)       │   │
│  │   (ВКС)      │    │   + screen share     │   │
│  └──────────────┘    └──────────┬───────────┘   │
│                                 │               │
│                    ┌────────────┼────────────┐  │
│                    ▼            ▼            ▼  │
│               🃏 Карты   📐 Расстановки  ✏️ Рисование │
│                  (модули)                       │
└─────────────────────────────────────────────────┘
```

**База** — обязательное ядро платформы:
- видеоконференция;
- холст (поле, зум, pan, sync, API модулей);
- демонстрация экрана на холсте (по умолчанию);
- комнаты, участники, роли, права;
- запись composite (видео + холст).

**Модули** — подключаемые инструменты на холсте:
- Метафорические карты (МАК);
- Расстановки по Хеллингеру;
- Рисование.

Модули регистрируются в ядре холста через единый API. Добавление новых модулей не должно требовать изменения ядра.

### 2.2. Принципы

| Принцип | Описание |
|---|---|
| Холст-центричность | Холст — ядро; модули монтируются в слот |
| Один активный модуль | В каждый момент на экране один модуль; state остальных сохраняется |
| Единый state сессии | Один JSON-state для sync, сохранения и записи |
| Модульность | Видео и холст не знают деталей модулей |
| Без сброса | Переключение Видео ↔ Холст и между модулями не уничтожает накопленное состояние |

## 3. Пользователи и роли

### 3.1. Роли

| Роль | Описание | Права |
|---|---|---|
| **Ведущий (терапевт)** | Создатель комнаты, проводит сессию | Полный доступ ко всем функциям, управление участниками и правами |
| **Клиент (участник)** | Приглашён по ссылке | Действия на холсте в рамках настроек комнаты и режима «хода» |
| **Наблюдатель** | Супервизор, стажёр | Только просмотр (read-only) |

### 3.2. Вход в систему

#### Терапевт (ведущий)

| Функция | Описание |
|---|---|
| Регистрация | Email + пароль, подтверждение email |
| Вход | Email + пароль; «Забыли пароль» |
| После входа | Личный кабинет (см. § 3.3) |
| В комнату | Из ЛК («Начать сессию») или по прямой ссылке комнаты с авторизацией |

#### Клиент (участник)

**Личный кабинет не предусмотрен.** Доступ только через комнату.

| Шаг | Описание |
|---|---|
| 1 | Переход по **уникальной ссылке** комнаты (доступ только у тех, кому ссылку передали) |
| 2 | Ввод **имени** (email **не** запрашивается) |
| 3 | Опционально: ввод **пароля комнаты**, если терапевт его включил |
| 4 | Назначение уникального **цвета** и `participantId` |

Данные гостя хранятся в сессии браузера (`sessionStorage`). Повторный вход по той же ссылке может подставлять имя автоматически.

**Запись клиенту** (если терапевт делится) — по **разовой ссылке**, без регистрации.

#### Наблюдатель

Тот же гостевой вход (ссылка + имя). Роль «Наблюдатель» назначает терапевт в сессии или через invite-ссылку с параметром роли.

### 3.3. Личный кабинет терапевта

Полноценный ЛК — рабочее место терапевта **вне сессии**. Клиентский ЛК не предусмотрен.

#### Структура разделов

| Раздел | Описание |
|---|---|
| **Главная** | Быстрый старт: «Создать комнату», «Начать сессию»; последние встречи |
| **Комнаты** | Список всех комнат; создание новой; редактирование и удаление |
| **История встреч** | Журнал завершённых сессий по всем комнатам (с фильтром по комнате) |
| **Записи** | Сквозной журнал всех записей (фильтр по комнате, дате); дубликат навигации из встреч |
| **Профиль** | Имя, email, смена пароля |

#### Комнаты

| Функция | Описание |
|---|---|
| Список | Название, дата последней встречи, число встреч в комнате |
| Создание | Новая комната с уникальной ссылкой и настройками по умолчанию |
| Карточка комнаты | Название, ссылка (копировать), пароль (вкл/выкл), модули, права клиентов |
| Действия | Редактировать, «Начать сессию», опционально — «Обновить ссылку» |
| **История встреч комнаты** | Основной контекст: список встреч **этой** комнаты; записи — внутри карточки каждой встречи |

#### История встреч (сессий)

Каждая **встреча** — один период работы в комнате от входа терапевта до завершения сессии.

**Список встреч** (таблица / карточки):

| Поле | Описание |
|---|---|
| Дата и время | Начало (и окончание) встречи |
| Длительность | Фактическая продолжительность |
| Комната | Название комнаты, ссылка на карточку |
| Участники | Кратко: «Ольга, Ирина, +1 наблюдатель» |
| Запись | Есть / нет; ссылка на просмотр |
| Холст | Есть сохранённый снимок state |

**Карточка встречи** (детальный просмотр):

| Блок | Содержание |
|---|---|
| **Участники на встрече** | Список всех, кто был в сессии: отображаемое имя, роль (клиент / наблюдатель), время входа и выхода (если доступно) |
| **Холст** | Просмотр финального state (карты, фигуры, рисунок) или снимок на момент завершения |
| **Запись** | **Основное место:** плеер / скачивание MP4 в карточке встречи (если запись включалась) |
| **Метаданные** | Комната, дата, длительность, использованные модули |

Участники сохраняются **как вводили имя при входе** (без email). При одинаковых именах в журнале — с указанием роли и порядка входа; внутренний `participantId` хранится в данных, в UI может не показываться.

#### Записи (навигация и хранение)

**Логика:** запись всегда принадлежит **встрече** → встреча принадлежит **комнате**.

```
Комната  →  Встреча  →  Запись (+ снимок холста, участники)
```

| Уровень | Где смотреть запись |
|---|---|
| **Основной** | Комната → история встреч → карточка встречи → ▶ запись |
| **Дополнительный** | Раздел «Записи» в меню ЛК — сквозной список с фильтром по комнате и дате |

| Функция | Описание |
|---|---|
| Привязка | Запись без встречи **не создаётся** |
| Список «Записи» | Дата, комната, длительность, участники (кратко); переход в карточку встречи |
| Действия | Просмотр, скачать, удалить |
| Sharing | Разовая ссылка клиенту (без регистрации), срок действия |
| Хранение | ≥ 30 дней; физически — `roomId → meetingId → recording` |

#### Профиль

| Функция | Описание |
|---|---|
| Данные | Имя, email, смена пароля |

#### Комната vs встреча

| Понятие | Описание |
|---|---|
| **Комната** | Многоразовое пространство: постоянная ссылка, настройки, серия встреч |
| **Встреча (сессия)** | Один конкретный seance: участники, state холста, запись, запись в истории |

Терапевт может иметь **несколько комнат** (разные клиенты, группы, настройки).

### 3.4. Идентификация участников

| Правило | Описание |
|---|---|
| Уникальность | Каждый участник получает уникальный `participantId` и цвет |
| Одинаковые имена | Допускаются; различие — цвет, id, уточнённое имя |
| Дубликат имени | При входе подсказка: «Уточните имя (например, Мария К.)» |
| Переименование | Терапевт может переименовать участника в sidebar |
| Права и «ход» | Привязка к `participantId`, не к строке имени |

## 6. База: Холст

| Функция | Описание |
|---|---|
| Поле | Фиксированное (экран или формат A3), визуальные границы |
| Фон | Белый, без серых подложек |
| Зум | 50%–200%, колёсико / кнопки +/− |
| Pan | Панорамирование внутри поля при зуме > 100% |
| Сетка | Опциональный фон для ориентира |
| Границы | Объекты не выходят за пределы поля |
| Слои | Z-index внутри модуля; PiP видео поверх холста (база) |
| Sync | Real-time синхронизация между участниками |
| Сохранение | State после завершения сессии |

### 6.1. Демонстрация экрана (базовая функция)

Демонстрация экрана — **функция холста по умолчанию**, не модуль.

| Правило | Описание |
|---|---|
| Отображение | Поток экрана в основной области холста |
| Видео | Участники в PiP (как при работе с модулями) |
| Кто может | По умолчанию — **ведущий**; опция «клиент может шарить экран» |
| Одновременность | Не более одного активного screen share в комнате |
| И модуль | **v1:** экран **или** модуль, не одновременно; state экрана сохраняется при переключении |
| Индикация | Баннер «Идёт демонстрация: [Имя]» |

## 7. Интерфейс и навигация

### 7.1. Глобальный layout

**Sidebar (слева):**
- верх: список участников с видео-миниатюрами;
- низ: инструменты (Экран, Карты, Расстановка, Рисование, Чат, Настройки);
- в самом низу: переключатель «Видео» / «Холст».

**Main area:** ровно одно из трёх состояний.

### 7.2. Состояние 1: Сетка видео

- По умолчанию при входе в комнату.
- Плитки 2×2, 3×3 и т.д. по числу участников.
- Имя, индикатор речи; активный участник подсвечен.
- Hover → иконка ⛶ (развернуть). Клик → Состояние 2.

### 7.3. Состояние 2: Полноэкранное видео

- Одно видео на весь main area.
- Остальные — только в sidebar.
- Возврат: кнопка ▢▢ «Свернуть» (не ✕) или Escape.
- Полноэкранный режим — для **одного** видео, не для всей сетки.

### 7.4. Состояние 3: Холст + PiP

- Активируется: инструмент (модули / экран) или кнопка «Холст».
- Холст на весь main area.
- PiP — активный участник, правый верхний угол.
- Hover PiP → ⛶ развернуть на весь main area (холст под затемнением).
- Кнопка «Видео» → Состояние 1.

### 7.5. Переключение состояний

| Из | В | Действие |
|---|---|---|
| Сетка | Fullscreen | ⛶ на плитке |
| Fullscreen | Сетка | ▢▢ или Escape |
| Сетка | Холст | Инструмент или «Холст» |
| Холст | Сетка | «Видео» |

**Важно:** содержимое холста (все модули, screen share state) **не сбрасывается**.

### 7.6. UX-правила (из прототипа)

- Фон холста — белый.
- Карты при hover — без затемнения; только translateY и тень.
- Иконки управления видео — по hover.
- Возврат из fullscreen — ▢▢, не ✕.
- Адаптивность: desktop, tablet, mobile.

## 8. Модули

### 8.1. Метафорические карты (МАК)

| Функция | Описание |
|---|---|
| Колоды | Несколько колод, у каждой своя «рубашка» |
| Форматы | WebP для показа; PNG/JPG — исходники |
| Тасовка | Ведущий: «Перетасовать» — перемешать, закрыть все |
| Переворот | Клик переворачивает карту (3D-эффект); повторный клик закрывает |
| Состояние | Открытые карты не закрываются автоматически |
| Управление | Перетасовать / Открыть все ↔ Закрыть все / Сбросить (закрыть, порядок сохранить) |
| Hover | Без затемнения; лёгкий подъём и тень |

**Права клиента:** переворачивать карты — **да** (если есть ход или ход выключен). Тасовка, выбор колоды — только ведущий.

### 8.2. Расстановки по Хеллингеру

| Функция | Описание |
|---|---|
| Фигуры | Цветные круги с текстовыми метками |
| Добавление | Только ведущий (быстрые кнопки + кастомный ввод) |
| Перетаскивание | **Свободный drag** по полю (mouse + touch); координаты x, y |
| Swap | **Не используется** |
| Наложение | Фигуры могут перекрываться; z-order: drag поднимает наверх, клик — на передний план |
| Удаление | Кнопка ✕ при hover; только ведущий |
| Владение | Ведущий **назначает** фигуру клиенту (`ownerId`); клиент двигает **свои** |
| Совместный режим | Toggle у ведущего: клиент двигает **любые** фигуры |

**Обратная связь при drag:** фигура полупрозрачная/уменьшенная; целевая при overlap — обводка (опционально).

### 8.3. Рисование

| Функция | Описание |
|---|---|
| Инструменты | Карандаш, ластик, линии |
| Цвет | Палитра |
| Очистка | «Очистить всё» — только ведущий |

**Права клиента:** рисовать — по toggle «Клиенты могут рисовать» (по умолчанию: да).

## 9. Права и «Передать ход»

### 9.1. Уровни прав

1. **Роль** (ведущий / клиент / наблюдатель)
2. **Настройки комнаты** (defaults для всех клиентов)
3. **Режим «хода»** (ограничение интерактива одним клиентом)

Персональные права на каждого участника — **не в v1** (достаточно «Передать ход»).

### 9.2. Defaults комнаты

| Действие | Клиент | Ведущий | Наблюдатель |
|---|---|---|---|
| Flip карт | ✅ | ✅ | ❌ |
| Тасовка, колода | ❌ | ✅ | ❌ |
| Добавить/удалить фигуру | ❌ | ✅ | ❌ |
| Drag **своей** фигуры | ✅ | ✅ | ❌ |
| Drag **любой** фигуры | ✅ если «Совместный режим» | ✅ | ❌ |
| Рисовать | ✅ | ✅ | ❌ |
| Очистить рисунок | ❌ | ✅ | ❌ |
| Screen share | ❌ (опция) | ✅ | ❌ |
| Запись | ❌ | ✅ | ❌ |
| Управление участниками | ❌ | ✅ | ❌ |

### 9.3. «Передать ход»

**Назначение:** при нескольких клиентах — поочерёдный интерактив на холсте, чтобы участники не мешали друг другу.

| Правило | Описание |
|---|---|
| Управление | **Только ведущий** |
| Включение | **Вручную** (не автоматически при 2+ клиентах) |
| Действия ведущего | Назначить ход клиенту; передать другому; забрать ход |
| Клиент | Не может сам получить или передать ход |
| С ходом | Один клиент интерактивен на активном модуле |
| Без хода (остальные клиенты) | Только просмотр холста |
| Ведущий | **Всегда** полный доступ, независимо от хода |

**UI:**
- кнопка «Передать ход → [имя]» у ведущего;
- «Забрать ход»;
- индикатор у активного: «Ваш ход» / «Ход: Ольга».

**Проверка доступа:**

```
canInteract(client) =
  turn.enabled == false  AND roomPermissions.allow(action)
  OR turn.enabled == true AND client.id == turn.participantId AND roomPermissions.allow(action)

canInteract(host) = always true
canInteract(observer) = false
```

## 10. Запись сессии

### 10.1. Требование

Запись — **единый видеофайл** (MP4/WebM), отражающий сессию как «психологический стол»: работа на холсте + контакт через видео.

**Не** «только видеопотоки» (как базовая запись Zoom без композита).

### 10.2. Содержимое записи

| Компонент | Описание |
|---|---|
| Холст | Активный модуль, screen share или пустой холст — **как в UI** |
| Видео | PiP активного участника при режиме «Холст»; сетка или speaker при режиме «Видео» |
| Аудио | Микширование участников |
| Переключения | Смена режимов Видео ↔ Холст фиксируется в записи |

### 10.3. Параметры

| Параметр | Значение |
|---|---|
| Инициатор | Только ведущий |
| Индикация | Метка «REC» у всех участников |
| Согласие | Явное уведомление «Идёт запись» |
| Хранение | Личный кабинет ведущего, ≥ 30 дней |
| Доступ | Скачивание; опционально ссылка клиенту |
| Обрыв | Сохранение частичной записи + уведомление |

### 10.4. Реализация (v1)

**Client-side compositor** у ведущего:
- сборка кадра: холст (canvas/DOM) + video tracks;
- `MediaRecorder` → chunked upload на backend;
- целевая задержка sync холст/видео: ≤ 500 ms.

Server-side compositing — резерв на будущие версии.

## Приложение A. Согласованные решения (хронология обсуждения)

1. Без экономики в текущем ТЗ.
2. Видео + холст = база; карты, расстановки, рисование = модули.
3. Screen share — базовая функция холста.
4. Запись = composite видео + холст (layout as shown).
5. Расстановки: free drag + z-order; swap не используется.
6. Один активный модуль; state сохраняется при переключении.
7. Права на уровне комнаты; «Передать ход» — вручную, только ведущий.
8. Фигуры «свои» — назначает ведущий.
9. Клиент по умолчанию может flip карт и drag своих фигур.
10. Терапевт: полный ЛК (комнаты, история встреч с участниками, записи); клиент без ЛК.
11. Email клиента при входе не используется; опционально пароль комнаты.
12. Одинаковые имена: id + цвет; уточнение имени; переименование терапевтом.
13. Обычного рисования достаточно; рисование поверх screen share — out of scope v1.
14. Записи: основное место — карточка встречи в комнате; раздел «Записи» — сквозной журнал с фильтрами.
